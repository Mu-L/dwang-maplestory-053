## 六、踩到的坑（下次直接照做）
1. **OrzRepacker 只要“曾经加载过”某个 root，之后 `save_node` 就写 `<名字>.bak` 而不是覆盖原文件**；原文件在被内存映射期间，覆盖/改名/截断都会 `Permission denied`。所以必须关掉 OrzRepacker 才能把 `.bak` 落盘（`promote_client.py` 干这个）。判断是否真的落盘只看原文件的体积/时间戳，别信 `{'ok': True}`。
2. 客户端组文件里的子节点名是**8 位补零**（物品 5150014 → 节点 `05150014`），而客户端 `String\Item.img` 里是**7 位**（`5150014`）。
3. 新建客户端组文件直接拷 048 的整份 img 会带上你不想要的物品（比如 2180000 洗点卷轴），拷完必须把不要的子节点删掉。
4. 服务端 xml 是从 048 的 xml 里抠块（`<imgdir name="05150014">` 整块），缩进从 2 空格改成 4 空格以对齐目标风格；客户端要用 img 的原图数据，不能拿服务端 xml 反生成（xml 里没有 icon 的像素）。

## 八、事故与修复：客户端 E_POINTER（-2147467261）

**现象**：这批数据打完后客户端一启动就白屏 + 韩文报错 `-2147467261`（= 0x80004003 = E_POINTER），进不到登录页；
不带 hook（WZ 模式）能到登录、选完角色，进游戏时同样报这个错。

**定位手段**：给插件加了一个文件追踪（改 `Hook/ResMan.cpp`，把每一次 `.img`/`.wz` 打开和资源请求写进 `<客户端目录>\resman_trace.log`）。
注意：Release 版编译时 `IS_DEBUG_MODE=0`，原来 `DebugFileAccess` 那套 `DEBUG()` 日志**全被编译器丢掉了**，所以之前开它什么也看不到。

**日志**：trace 最后一行停在
```
[fs W] Data/Quest/Check.img      -> ok
[fs W] Data/Quest/QuestInfo.img  -> ok
（之后没有下一行 → 客户端解析 QuestInfo.img 时炸的）
```

**根因**：OrzRepacker 保存 img 时，把头部 offset 0x0C 的 4 字节字段（属性表偏移/字符串池大小类）**算大了**。
逐字节比对（迁移前备份 vs OrzRepacker 写出的文件）：整个文件**只有 1 个字节不同**（就是这个字段）+ 尾部多出 2901 字节，其余完全一致。
QuestInfo.img 该字段 211840 → 216192（+4352），而新增字符串其实是**追加在文件尾部**、并没有进字符串池 → 客户端按错误偏移读属性表 → 越界 → E_POINTER。

**修复**：把 4 个 Quest img 的该字段**改回迁移前的值**（其余字节保持 OrzRepacker 写的内容）：

| 文件 | 字段 迁移后 → 修正为 | 体积 |
|---|---|---|
| `Quest\Check.img` | 214400 → 211328 | 184139 |
| `Quest\Act.img` | 214656 → 211584 | 238319 |
| `Quest\QuestInfo.img` | 216192 → 211840 | 342387 |
| `Quest\Say.img` | 214912 → 211840 | 827929 |

**验证**（本地用追踪版 Hook 启动）：客户端顺利过 QuestInfo → 继续加载 UI/物品/NPC → 连上频道进入游戏；
我改过/新建的物品文件（`Cash 0504/0509/0514/0515/0521/0531`、`Consume 0212`、`String/Item`）全部被加载且 `ok`。

**以后照做**：凡是 OrzRepacker 保存过、且这次是"新增节点/新增字符串"的 img，若客户端加载报 E_POINTER，
先把头部 offset 0x0C 的 4 字节改回改动前的值再试。本次地图文件该字段与备份一致（没被改坏），物品文件也正常。

**工具**：`地图迁移\Hook-带资源追踪.dll`（诊断版插件，改名成 `Hook.dll` 放进客户端即用，会在客户端目录写 `resman_trace.log`）；
正式版在 `地图迁移\备份\Hook-1.1.7-正式版.dll`。

## 九、客户端 1.1.10：商城窗口偏移/消失（开着 UI 进商城出来就偏，装备/技能/物品/小地图）

**现象**：游戏里开着若干 UI（装备 E、技能、物品、小地图，甚至只开任务助手）进商城、再出来，窗口会偏移；
多进几次就整片偏到屏幕外"不见了"，重登才恢复。

**定位**（用插件自带的 `DebugUiLayout = true` 文件日志 `uilayout_trace.log`，本次为它新加）：

进商城时客户端把这些窗口**移到屏幕外藏起来**，销毁时又把"屏幕外坐标"当成窗口位置存了下来：

```
[stage] OnSetCashShop enter, gameStage 0            # 插件把"局内"标志清掉
[save] uiWnd index=1 x=3388 y=-75  ... origin=-1    # 装备（CWnd::Destroy -> sub_6DD737 -> CConfig::SetUIWndPos）
[save] uiWnd index=2 x=2866 y=-85  ... origin=-1    # 物品
[save] uiWnd index=3 x=3213 y=-75  ... origin=-1    # 技能/属性
[save] uiWnd index=4 x=2517 y=-85  ... origin=-1    # 小地图
[cwnd] caller=00665967 stock=2525,-100 ...          # 下次建窗直接按这个值建（CUIMiniMap::Init）
```

关键点：

* 存位置：`CWnd::Destroy [sub_750C0D]` → 虚表 slot 4 `sub_6DD737` → `CConfig::SetUIWndPos [sub_471A38]`；
  槽号 = 构造时 `sub_6DD423` 的第一个参数（小地图 4、任务助手 13、装备/物品/技能 1/2/3）。
* 取位置：`CUIMiniMap::Init [0x66507A]`（以及其它窗口）用 `CConfig::GetUIWndPos [sub_4719CB]` 读回来，
  直接当**设计坐标**喂给 `CWnd::CreateWnd`。
* 所以"在商城侧存、在游戏内取"就会把偏移烙进去，每进一次商城叠一层；
  小地图每个对象只允许建一次窗口（对象内 `+0x5E0` 标志），建到屏幕外就再也不会自愈。

**走过的弯路**（别再来一次）：曾经在存位置那条路上把原点强制切回"游戏内"，想让"绝对坐标==设计坐标"；
实测反而更糟 —— 客户端自己在这条路上已经补偿了原点，把原点换掉等于让它把没补偿的值写回去，
任务助手每趟商城固定漂 (283,84)：908→1191→1476。该改动已回滚，注释留在 `Hook/UiLayout.cpp`。

**修复**（client-dist 1.1.10）：在写窗口位置表处**丢弃屏幕外坐标**（槽位保留上一次正常值，窗口回原位），
小地图建窗再加一道屏幕外兜底（回客户端默认 8,8）。实测日志里商城期间的写入全部 `REFUSED (off screen)`，
出来以后各窗口存的都是正常值（装备 48,48 / 物品 693,103 / 技能 397,45 / 小地图 8,8）。

**以后排查排版问题**：`v53-client\config.ini` 里 `DebugUiLayout = true`，跑一次看 `uilayout_trace.log`
（`[stage]` 阶段切换、`[origin]` 原点切换、`[cwnd]` 每次建窗、`[destroy]` 小地图/任务助手销毁、`[save]` 窗口位置写入）；
平时保持 `false`。
