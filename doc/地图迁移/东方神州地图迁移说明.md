## 二、为什么是这些文件（依赖怎么找）

### 1. 地图本体
```
Map.wz/Map/Map<首位数字>XXXXXXX.img
```
`701000000` → `Map.wz/Map/Map7/701000000.img`。
里面包含 `info`（bgm / mapMark / VRTop/Left/Bottom/Right / town / returnMap / fieldLimit）、
`foothold`（碰撞）、`ladderRope`、`portal`（含 `tm` 目标图）、`life`（npc/mob 刷新）、
`reactor`、`back`、图层 `0~7`（`obj` + `tile`）。

### 2. 从地图里读出来的引用
| 地图里的字段 | 去哪里找 |
|---|---|
| `info/bgm = "BgmCN/GoShanghai"` | `Sound.wz/BgmCN.img/GoShanghai` |
| `info/mapMark = "ShangHaiCN"` | `Map.wz/Map/MapHelper.img/mark/ShangHaiCN` |
| 图层 `N/info/tS = "ShanghaiCN"` | `Map.wz/Tile/ShanghaiCN.img`，再用 `tile/u` + `tile/no` 定位贴图 |
| 图层 `N/obj/M/oS = "ShanghaiCN"` + `l0/l1/l2` | `Map.wz/Obj/ShanghaiCN.img/<l0>/<l1>/<l2>` |
| `back/K/bS = "ShanghaiCN"` + `no` | `Map.wz/Back/ShanghaiCN.img/<no>` |
| `life/type=m,id=9619999` | `Mob.wz/9619999.img` + `String.wz/Mob.img/9619999/name` |
| `life/type=n,id=9310019` | `Npc.wz/9310019.img` + `String.wz/Npc.img/9310019/...` |
| `portal/pn/tm` | 目标地图 ID（**必须在同一批里**，否则传送门无效） |
| `portal/script = market09 / pvp00 / pvp04` | 服务端脚本（本次**没有**对应脚本，见第七节） |

### 3. 两端的形态不一样
* **服务端**：读的是 XML，路径 `gms-server/gms-handler/wz/<WZ名>/…/<名字>.img.xml`，字符串在 `wz-zh-CN/String.wz/*.img.xml`（语言目录优先）。
* **客户端**：`config.ini` 里 `UseImgMode = true` 时读 `Data/<WZ名>/…/<名字>.img`（二进制 img，不是 xml，也不是 wz）。
  所以**客户端只要 img，不需要重新打包 wz**；但**根目录那套 .wz 必须让位**，即 `UseImgMode` 要是 `true`。

## 七、已知问题 / 需要你测的时候留意

1. **冒险大擂台（7800000xx / 7810000xx / 7820000xx）的玩法**
   这 14 张图在地图 xml 里有 `pvp` 节点，`fieldLimit = 252 / 254`，CMS 里是靠 PvP/擂台系统跑的。
   GMS v053 的服务端代码里**完全没有 `pvp` 相关处理**（全局搜过），客户端 v053 也不一定认这个节点。
   预期结果：**地图能正常进、能站、能看，但「擂台玩法」（计分/胜负/自动开赛）不会生效**，
   而且这几张图里刷的是占位怪 `9619999`（CMS 原版就是拿它当假人）。
   要真正跑起来得写服务端逻辑 —— 属于改代码，本次没做。
2. **上海豫园（701000200）的两个传送门脚本**
   `pvp00`、`pvp04`（`tm = 999999999`）以及 701000210 的 `pvp00`，
   服务端 `bms/Script` 下没有对应脚本。表现是**点了没反应**（不会崩）。不影响其它图。
   `market09` 同理（同目录只有 `market.s`）。
3. **`9619999` 的名字是 `gasangmob`**（CMS 原版占位名，韩语「假想 mob」的音译），
   打到它时怪物名会显示这个。想好看可以改名：客户端 `String/Mob.img/9619999/name` +
   服务端 `wz-zh-CN/String.wz/Mob.img.xml` 里同一个 id，两边都改。
4. **781000003 / 782000002 两张图 CMS 原版没有字串名**（它们也没有任何传送门指向，属于预留图）。
   本次按同组规律补名：`东方神州 / 多数怪物大擂台4`、`东方神州 / 障碍比赛大擂台3`。
   服务端 `china` 容器里对这两个 id 用的是另一套名（`少林寺 / 怪物大擂臺4`、`少林寺 / 障礙競走大擂臺3`），
   所以**服务端和客户端这两张图的名字会不一致**，不影响任何功能。
5. **701000100 的名字，两端也不完全一致**：
   客户端用 CMS v48 的名字「上海临时机场」，服务端 `china/701000100` 是「上海城市广场」。
   同样只是显示差异。想统一就以一边为准改另一边。
6. **世界地图（WorldMap）没迁**
   游戏里的「世界地图」是按 `Map/WorldMap/WorldMap%02d.img` + `WorldMap.img` 表驱动的，
   东方神州没有对应的一张。**不影响进图**，只是世界地图界面里看不到这一片。
   要补的话源在 `cms048\cms-img\Data\Map\WorldMap\WorldMap0.img` / `WorldMap1.img`（CMS 命名和 GMS 不一样，需要自己对接）。
7. **客户端 `Data\Map\Map\Map7` 是新目录**，如果你以后用工具重新解包 `Map.wz` 覆盖 Data，
   这些新增会没掉 —— 重新跑一遍 `迁移包\客户端\Data` 的覆盖即可。
8. **根目录的 `.wz` 没动**：`v53-client\Map.wz`、`String.wz` 等还是老样子。
   如果哪天把 `UseImgMode` 关掉，这些新地图就看不到了（这是预期行为）。

## 八、以后自己迁别的图（通用流程）

1. **定范围**：拿到地图 ID 清单（像这次的 `doc/cn.img.xml`）。
2. **导出/找到源素材**：服务端 XML 一份、客户端 IMG 一份（源版本自己的 `Data` 目录）。
3. **扫依赖**（`map-migration\tools\analyze_maps.py`，改一下目录就能用）：
   把每张图的 `info/bgm`、`info/mapMark`、每层 `info/tS`、所有 `obj/oS+l0/l1/l2`、
   所有 `back/bS+no`、`life/type+id`、`portal/tm+script`、`reactor/id` 全抓出来汇总。
4. **和目标端对比**（`scan_target.py`）：逐个去目标客户端 `Data` / 服务端 `wz` 里看文件在不在，
   得到「缺哪些」的清单。
5. **拷贝**：
   * 服务端：XML 直接放对应目录（缩进/换行对齐原文件，新目录如 `Map7` 直接建）。
   * 客户端：IMG 直接放 `Data` 对应目录。
   * **只补缺的**，已存在的不要用源版本覆盖（版本可能不同，会把现有汉化/修正冲掉）。
6. **字串**：
   * 服务端 `wz-zh-CN/String.wz/Map.img.xml`：注意 `buildMapName` **只认两层**
     （容器 → 数字 ID），放到第三层（如 `china/chinese/<id>`）是读不到的。
   * 客户端 `Data/String/Map.img`：用 OrzRepacker 加一个容器（名字随意，客户端会遍历所有容器，
     因为 exe 里没有任何区域名常量），里面每个地图 ID 一个节点，写 `streetName` / `mapName`。
7. **收尾自检**：BGM 曲名要在文件里（不只是文件存在）、mapMark 要有、portal 的 `tm` 必须都在本批内。
8. **备份**：改之前先把原文件复制到 `E:\game\ms\gms053\地图迁移\备份\<日期>-<批次名>\`。
