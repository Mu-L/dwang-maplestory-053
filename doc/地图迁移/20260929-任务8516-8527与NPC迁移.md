## 六、工具与踩到的坑
工具（都在 `gms53-Server\doc\地图迁移\tools\`）：
- `cms48_tool.py`：改服务端 xml（`quests` / `life` / `npc`，加 `--apply` 才落盘），`diag` 用来打印 foothold 几何对照
- `cms48_client.py`：改客户端 img，走 OrzRepacker 的 MCP（`apply_all` / `verify_baks` / `verify_baks2`）

坑 1：**create_child 必须自己把父节点建出来**。第一版 `ops_of()` 直接遍历任务块，漏掉了任务根节点（`8516` 本身没建），结果里面 `0`/`1` 被建到了 img 的根上（Act/QuestInfo/Say 都多出两个垃圾根节点）。现在先 `create_child(name=任务号)` 再往下递归，并且顺手把误建的根 `0`/`1` 删掉。

坑 2：**OrzRepacker 一个 root 一旦被别的会话加载过，`save_node` 就不会覆盖原文件，而是写 `<文件名>.bak`**；而且原文件被内存映射占用期间，改名、覆盖、截断全部失败（`user-mapped section open` / `Permission denied`）。必须关掉 OrzRepacker 才能把 `.bak` 落盘。校验 `save` 是否真的落盘，只看原文件的体积/时间戳，别信 `{'ok': True}`。

坑 3：客户端 `Data\Item\Etc\0403.img` 的子节点是 8 位补零（`04031326`），而 `Data\String\Item.img\Etc\` 是 7 位（`4031326`），查节点时别用错位数。
